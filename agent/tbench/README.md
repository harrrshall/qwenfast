# terminal-bench for the qwenfast agent

runs [terminal-bench](https://www.tbench.ai) through [harbor](https://github.com/harbor-framework/harbor) with the same pi harness, models and complexity router the agent daemon uses. every task is a real multi step terminal job in its own docker sandbox, graded by hidden tests, so a run measures what the agent actually gets done, how fast, and at what cost.

`QwenfastPiAgent` extends harbor's built in pi agent. per task it writes the two qwenfast tiers into pi's `models.json` (generated by `node src/cli.ts models-json`, the same definitions the daemon uses), picks a tier, and runs pi headless with the autonomy prompt.

| `QFA_TIER` | what runs |
|---|---|
| `small` | qwen3.6-35b-a3b, thinking off |
| `medium` | qwen3.8-27b on qwenfast, effort medium |
| `large` | qwen3.8-27b on qwenfast, effort xhigh |
| `auto` | the router (`node src/cli.ts route --judge`): lexical score, small model judge for borderline tasks |

the chosen tier and the router's reasons are saved per trial as `agent/qfa-route.json`.

## where it runs

terminal-bench images are x86_64, so the sandboxes run on a linux vm with docker (a jarvislabs cpu vm in the same region as the gpu box works well; 8 vcpus runs 8 tasks at once). the models stay on the gpu box.

```bash
# on the vm, once
mkdir -p ~/qfa && tar xzf agent.tgz -C ~/qfa     # agent/ without node_modules
sh ~/qfa/agent/tbench/vm_setup.sh                 # node, npm ci, venv with harbor and this adapter
printf 'QFA_BIG_URL=...\nQFA_SMALL_URL=...\nQFA_API_KEY=...\nQFA_BOX_SSH=root@<box ip>\n' > ~/qfa/bench.env && chmod 600 ~/qfa/bench.env
```

with `QFA_BOX_SSH` set, `run.sh` opens an ssh tunnel to the gpu box bound to the vm's private address and points pi at it; the task containers reach it there. the jarvislabs https proxy closes responses after about two minutes, so without the tunnel long thinking turns get cut. the vm's ssh key must be authorized on the box (`jl ssh-key add`, plus `authorized_keys` on an already running box).

## run

```bash
sh ~/qfa/agent/tbench/run.sh auto                       # full dataset, 8 at a time
N=4 sh ~/qfa/agent/tbench/run.sh large --n-tasks 10     # a quick slice
DATASET=terminal-bench@2.0 sh ~/qfa/agent/tbench/run.sh small --n-attempts 5   # pass@k and pass^k
```

each run ends with `report.py`, which prints and saves `report.json` next to the harbor job: pass rate, pass@k and pass^k when attempts > 1, wall time per task, agent turns, input and output tokens, decode tok/s, the tier mix the router chose and the pass rate per tier.

compare configurations by running the same dataset with each `QFA_TIER` and diffing the reports.
